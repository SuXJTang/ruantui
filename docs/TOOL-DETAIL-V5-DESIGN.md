# 工具详情面板 v5 设计文档

> 制定：2026-11-21 | 目标版本：v5.0（`modal.js` 重写 + `.modal-detail` 样式）
> 起因：桌面端点击卡片弹出的详情只有 560px 宽，正文一行 30 字，两段长文都被折叠成 3 行
> 要点两次「展开全文」；分享区占掉 1/4 高度却没主行动按钮。

---

## 一、现状盘点（实测 1440×900）

弹窗实测 **560 × 692**，内部区块高度：

| 区块 | 高度 | 问题 |
|---|---|---|
| header | 60 | 图标 60px 偏小；下载数孤立在右侧 |
| 详细介绍 | 137 | 3 行折叠 + 「展开全文」 |
| 使用说明 | 137 | 同上，与上一段视觉上完全对等，主次不分 |
| 链接 | 0 | ok影视 无外链时整块消失 |
| 专属下载 | 0 | 异步，未登录时不显示 |
| 标签 | 56 | 正常 |
| 分享 | 156 | 占 1/4 高度；「保存二维码」几乎没人用 |

**核心矛盾**：这是全站信息密度最高的界面，却按「小对话框」的规格设计。

## 三、功能矩阵：保留 / 合并 / 移除

| 现有能力 | 新归属 | 变化 |
|---|---|---|
| 去官网 | 右栏操作卡 · 主按钮 | 从页面中部提到视觉重心 |
| 下载 | 右栏操作卡 · 主按钮 | 同上 |
| 专属下载（VIP / 登录，异步） | 右栏操作卡下方独立行 | 逻辑不动，位置提前 |
| 收藏 | 右栏操作卡 · 次按钮 | **新增**（原来只能点卡片角标） |
| 复制链接 | 右栏「手机打开」卡 | 保留 |
| 复制推荐语 | 右栏「手机打开」卡 | 保留 |
| 保存二维码 | — | **移除**（右键图片即可保存） |
| 展开全文 / 收起 | 桌面**移除**；≤900 单列时保留 | 桌面有空间，不该让用户点两次 |
| 「链接」独立区块 | — | 合并进操作卡 |
| 下载数 | header + 信息卡 | 保留 |
| 浏览次数 | header + 信息卡 | **新增展示**（原来详情里没有） |
| 评分（rating） | header + 信息卡 | **新增**（DB 有字段，此前未用；无值时整行隐藏） |
| 收录时间（created_at） | 信息卡 | **新增** |
| 下载权限（download_tier） | 信息卡 | **新增**（VIP 专属一目了然） |
| 浏览量递增 / 下载计数 | `openModal()` 原逻辑 | 不动 |

**明确不做**：评论区、相关推荐、截图轮播（数据里没有对应字段，不造内容）。

## 四、交互

| 场景 | 行为 |
|---|---|
| Esc / 点遮罩 / 点 ✕ | 关闭（不变） |
| 从卡片「下载」按钮进入 | 打开后高亮右栏操作卡（原来滚到「专属下载」区块，现在无需滚动） |
| 收藏 | 图标切换 + 轻量缩放反馈，状态写回 `isFavorited` |
| 二维码 | `loading="lazy"`，加载失败降级为纯文本链接（现有逻辑保留） |
| 长文 | 桌面完整显示；≤900 单列时 >66 字折叠 |
| 滚动 | 桌面左栏跟随面板滚动；右栏 sticky |

## 五、实现（文件与类名）

| 文件 | 改动 |
|---|---|
| `modal.js` | `openModal()` 重写为左右两栏模板；新增 `detailActionsHTML` / `detailInfoHTML` 两个渲染函数 |
| `style.css` | 新增 `.modal-detail` 及子块（`.detail-head` `.detail-grid` `.detail-main` `.detail-side` `.action-card` `.info-card` `.share-card`），只在详情弹窗上生效 |
| `index.html` | 详情弹窗的 `.modal` 加 `modal-detail` 类；其余弹窗（管理面板 / 表单 / QQ / 反馈 / 赞赏）不动 |
| `engagement.js` | 导出 `window.getFavorites` 与 `window.updateFavCount`（弹窗收藏后要同步筛选栏计数） |

> 旧的 `.modal-header` `.modal-section` `.modal-text` `.modal-link` `.share-body` `.share-actions` `.share-act-btn` 在改造后**已无任何 JS/HTML 引用**（全项目 grep 确认），只是还留在 `style.css` 里。管理面板与表单弹窗并不使用这些类名，可以后续单独清理。仍被使用的只有 `.modal-tag` `.modal-tags` `.modal-toggle` —— 不要删。

**约束（来自 AGENTS.md）**：
- 不改 `incrementDownload` / `incrementView` / `loadVipDownload` 的调用时机
- VIP 链路仍走 `get_download_url()`，前端不得出现真实链接
- 弹窗背景必须实色（`--s3`）
- 改完 `node --check modal.js`，并验证三个视口
- 版本号 `?v=89 → 90`、`CACHE_VERSION v97 → v98`

## 六、验收标准

1. 1440×900：面板宽 ≥ 900px，正文一行 ≥ 40 字，右栏操作卡完整可见
2. 现有 12 项能力逐条可达（按第三节矩阵打勾）
3. 390×844：单列，操作卡在标题下方，长文可折叠，无横向溢出
4. 768×1024：单列（≤900 断点），操作卡紧随 header
5. 统计：点「下载」后 `downloads` +1；打开弹窗后 `views` +1
6. 暗色：面板实色、信息卡与正文对比度正常
7. `node --check modal.js`、CSS 括号配对、类名守恒（旧类名不删，只新增）

## 七、独立复核结论（2026-11-21）

改动完成后做了两轮独立只读复核（Claude Code 因本地网关不可用未参与，改由隔离子代理执行），结论与处理：

| 发现 | 判断 | 处理 |
|---|---|---|
| `modal.js` 收藏时调 `getFavorites`，但它只在 engagement.js 的 IIFE 内，没挂 window → 弹窗里收藏后筛选栏计数不更新 | **真 bug**（`typeof` 守卫让它静默跳过） | 已导出 `window.getFavorites`，并补上一直只有调用、没有实现的 `window.updateFavCount` |
| tier=user/vip 且未登录时，旧版会直接把下载链接渲染出来 | 旧版是**漏洞**，不是被丢失的能力 | 新版按 tier 加锁并给「登录后下载 / 开通 VIP」引导，属行为修正 |
| `window.downloadQR`（保存二维码）改造后无人调用 | 死代码 | 保留未删（无副作用），记录在此待清理 |
| 旧 `.modal-*` 类名在改造后已无 JS/HTML 引用 | 死 CSS | 本轮不删（AGENTS.md 要求删 CSS 逐项确认），记录待清理 |
| 弹窗内下载数点完不刷新（旧版靠 `.tool-dl-num`） | 体验回归 | 头部下载数加 `data-dl-stat`，点击下载后用返回值刷新 |

复核确认无重复事件绑定；`incrementDownload` 全站仅一个调用点，不会重复计数。
